# OptChat v2 reference

Author: Victor Taelin. [Upstream recipe](https://gist.github.com/VictorTaelin/91837951a5ce5b38f341ec1ba1df6449); attribution is in [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md).

The implementation follows the bundled, unmodified [OptChat v2 specification](optchat.v2.md), reviewed on **2026-10-12**, with SHA-256 `12f300f760af82bc07bc5201051d1267824ded09c9def8186e4f8144368038d8`. This reference maps that specification to the current implementation and identifies optional policies and integration limits.

## Implementation mapping

| Contract | Implementation |
| --- | --- |
| Permanent log (§1) | `src/memory.ts`, `src/store.ts`: append-only originals, immutable nodes, one owner, durable writes. New long non-tool text becomes lossless consecutive chunks with a write-ahead intent and a receipt only on the final chunk. Existing records are not rechunked. Tool-result text retains its separate 30,000-character head/tail cap. |
| Binary tree and scheduling (§2, §4) | `src/memory.ts`: eight workers for chat, fewer-than-eight-unbuilt-leaves lookahead and ready merge queues. Small sources are their own nodes. Failed summaries never become clipped-source substitutes. Required failures stop the waiting turn visibly; new input retries failed work without timers. |
| Main and compaction views (§3.2, §4) | `src/memory.ts`: full rendered UTF-8 size includes labels, separators and `<chat>` framing. Main 128,000/64,000; compaction 32,000/16,000. Most-due eligible aligned siblings merge first, with oldest-first ties. Missing parents can delay completion of a batch. Main batches also advance the compaction view. |
| Restart state (§3.2) | `src/store.ts`, `src/memory.ts`: one atomic, versioned `view.json` stores both selections and unfinished batch flags. Legacy pair arrays migrate once. Log suffixes replay onto the saved selections; existing summaries are reused. |
| Shared prefix (§4, §5) | `src/prefix.ts`, `src/index.ts`, `src/compactor.ts`: common OptChat instructions, Pi's stable sections and complete tool declarations, then profile instructions. Global/project context, skills, user additions and finalized extension/MCP sections are retained. Operational sections follow the view. Retries snapshot the prefix, model, credentials and size policy once. |
| Compaction protocol (§4) | `src/prompts.ts`, `src/compactor.ts`: the leaf/merge tasks, 512-dash ruler and shortening correction follow the local task text verbatim. Context is a contiguous built prefix, ending before a leaf or through a merge, and stops at the first unbuilt original. There is no extra raw-call block for echo summaries. Replies above 512 UTF-8 bytes are shortened in the same conversation, at most five attempts; the shortest valid result can remain slightly over. Empty, tool-calling and cut-off replies are invalid; declared tools are never executed by the compressor. |
| Base turn (§6) | `src/index.ts`, `src/transcript.ts`: wait for prior originals and selected view nodes, render prior history before logging new input, then retain the complete current tool loop, delivered steering and reports. The view is the only continuity across turns by default. A failed required summary prevents the main provider request; waiting is cancellable. |
| Retrieval (§6) | `src/memory.ts`, `src/tools.ts`: numeric zoom/date and long-original paging, including logical chunk ranges. `src/agents.ts`, `src/agent-view.ts`: named zoom pages canonical retained child entries, including full retained arguments/results from before Pi compaction, plus a deduplicated live tail. Thoughts, injected view text and child image bytes are excluded. Existing descendant authorization remains in force. |
| Optional children (§6) | `src/agents.ts`, `src/index.ts`: asynchronous Pi SDK children, independent completion reports by default, journals and transcript retention. Actively working children cut off by close/crash/reload resume at interactive startup; intentionally stopped/paused children and headless runs do not auto-resume. Connected conversations recover handoffs. |
| Cache layout (§3.3) | `src/cache.ts`: complete blocks of four summary lines, separate framing, short-retention Anthropic marks at the last full group, two earlier groups when available, and the request end before dynamic status. Other providers use their native implicit caching. |
| Cache coordination (§3.3, §4) | `src/cache-gate.ts`: a process-local gate matches actual marked prefixes within provider lookback windows, partitioned by model, tools, instructions, account and routing. Known model minima are checked with the provider token-count endpoint before waiting. First response, failure, cancellation or lease expiry releases followers; unsupported counting/unknown models remain concurrent. No model keep-alive calls. |
| Defaults and optional policies | `src/settings.ts`, `src/profiles.ts`: replay off, refresh zero, summary acceptance 512 bytes, search off, grouped reports off. Missing keys take these defaults; explicit settings/models remain unchanged. Startup/settings expose `OPTCHAT_REFRESH_AT` overrides. New profiles request Haiku 4.5/xhigh; pinned Pi 1.0.2 clamps it to high and this is reported. |
| Historical imports | `src/import/`: a lighter integration policy retains selected user messages/final replies or notes, not a reconstruction of the full original tool log. Incoming history appends after existing permanent IDs. Staging reuses existing nodes/views and activates atomically only when the tree is ready. Default concurrency is eight, with the same leaf lookahead and ready merges; imports are not serial. Failures retain the journal for Resume. |

## Scope and limits

The full prompt is adapted, not verbatim: Pi uses `talk` for replies, run IDs for child names, integration-specific tool/status guidance and historical-import labels. The common prompt retains user-requested delegation and v2's compression priorities. Profile instructions are shared with compactions. `src/prompts.ts` holds the prompt strings; tool descriptions stay with their tools.

Pi exposes rendered instructions and loadout declarations before a canonical request exists. Background/import compactions use that current configuration; after `context_with_system`, they use its finalized declarations and structured sections. Instructions or tool changes introduced by a later turn/reload apply when Pi makes them available. An extension that subsequently rewrites the native request can change the prefix outside OptChat's common builder. The native transport tests cover the finalized Pi/MCP path, reports, reloads and configuration changes; they do not claim that arbitrary later provider hooks preserve equality.

Previous-exchange replay, mid-turn refresh and a larger summary tolerance are explicit optional departures. The base retains the complete live turn, which can exceed a finite provider window; the rendered view budget is not a whole-request budget. Child working contexts may use Pi compaction while their retained logs remain retrievable. Paging itself is required by local v2 §6.

Profiles, the inspector, usage ledger, connected windows and source adapters are integration choices. Imports preserve permanent IDs but intentionally retain less than a complete source session. Computer use, distributed storage and always-on hosting are outside this work.

Offline fixtures verify serialization, scheduling, recovery and request coordination. They do not measure live model quality, provider cache-hit rates or billing savings. Atomic-write/restart tests do not simulate every filesystem or power-loss failure. Earlier README experiments are not validation of this implementation.
